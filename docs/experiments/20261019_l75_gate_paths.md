## 1. 최종 결정과 핵심 결과

**Candidate를 기본 경로로 유지하고 이번 비교를 종료한다.** M20에서 작은 성능 차이, 양호한 reset/swap 진단, 단순한 구조와 적은 파라미터·근사 연산량을 함께 고려해 선택했으며, M8/M75 전달성까지 확인했다. Candidate의 best PPL은 세 M에서 모두 가장 낮다. Final은 M20/M75에서 가장 낮고 M8은 independent가약0.07% 낮아 사실상 동등하다. Separate_head는 best/final 모두 세 M에서 가장 높았다.

동일 M에서 source·실행 식별자 이외의 Config와 dataset manifest가 같다. Python3.13.15·PyTorch2.11.0+cu128·Transformers4.45.2·CUDA12.8이다. M20은 `fb9ba36`, 전달성 run은 `dde0e8f`/`1deef36`/`35eb7f2`이며 후자의 commit 사이에 `src/grt`·카탈로그·학습/분석 진입점 변경은 없다. 같은 seed·조건이 초기화 RNG 소비·dropout 표본까지 같다는 의미는 아니다.

| 경로 | MLP에 제공할 feature F | 추가 feature head |
|---|---|---|
| independent | 원래 token embedding의 독립 attention pooling, 전역[B,D] | 없음 |
| separate_head | 최종 출력 정규화 직전 register hidden H_reg의 Linear(D,D), 슬롯별[B,M,D] | D→D, bias 포함 |
| candidate · 채택 | 최종 정규화를 마친 실제 candidate C 공유, 슬롯별[B,M,D] | 없음 |

세 경로 모두 `V=RegisterAttention(F,S,S)`로 segment 시작 state를 참조하고 `concat(F,V)`의2D를 GELU MLP(hidden512)에 넣어 슬롯별 scalar write를 예측한다. Independent는 전역 hidden에서 M개 출력, 공유 경로는 슬롯별 hidden에 해당 출력 weight 행을 적용한다. Query 내용·개수도 달라 전체 gate 설계의 비교로 해석한다.

```text
[X; S] ─ NeoX stack ─ 기존 최종 출력 정규화 ─ [Y; C]
F ─┬─ concat(F,V) ─ GELU MLP ─ sigmoid ─ w
S ─┴─ RegisterAttention(F,S,S) ─ V
S_next = (1-w) * S + w * C
```

Token은 모든 layer에서 시작 S만 읽고 중간 candidate hidden을 K/V로 읽지 않는다. 전체 stack 뒤 write-back은 한 번이며 기존 candidate 출력 경로·명칭은 유지한다. 별도 gate linear는 separate_head에만 존재한다.

## 7. 원 RMT와 학습량 비교

비교 대상은 [NeurIPS2022 원 RMT §4·Table2](https://papers.neurips.cc/paper_files/paper/2022/file/47e288629a6996a17ce50b90a056a0e1-Paper-Conference.pdf)와 [저자 공개 run CSV](https://github.com/booydar/LM-RMT/blob/main/experiment_results/results_wt103_enwik8_all_parameters.csv)다. WT103의82개 run은 L150/batch60이34개, L50/batch128이48개이며 모두200k updates·고정 L이다. 본문은 linear schedule, CSV는 cosine이므로 같은 학습 프로토콜로 표현하지 않는다.

| 새 target 노출량 | 현재 GRT 각 run | 원 RMT L150 | 원 RMT L50 |
|---|---:|---:|---:|
| Token 단위·L·global batch | BPE / 75 / 256 | word / 150 / 60 | word / 50 / 128 |
| Updates | 40k | 200k | 200k |
| 누적 새 targets | 실제767,950,848 | 명목1,800,000,000 | 명목1,280,000,000 |
| 코퍼스 통과량 | 약6.48회 | 약17.44회 | 약12.40회 |
| 현재40k의 상대 노출량 | 기준 | 약37.2% | 약52.3% |
| 현재40k를 원 논문 step으로 환산 | 기준 | 약74.4k | 약104.6k |
| 논문 전체 노출량을 현재 step으로 환산 | — | 약107.6k | 약76.5k |

새 targets=B×L×updates이며 memory와 과거 BPTT replay는 제외한다. 통과량의 분모는 현재 manifest118,436,938 BPE와 [WikiText 원 논문 Table1](https://arxiv.org/pdf/1609.07843)의103,227,021 word tokens다. Tokenizer 차이를 고려한 근사이고 원 RMT targets는 실제 counter가 아니다. K3 문맥도 현재300 BPE(평균 약261 word 상당), 원 RMT L150: 600 words / L50: 200 words로 다르다. 원 RMT 약151M·Transformer-XL·word/adaptive softmax·test PPL과 현재 약18M·NeoX·BPE/full softmax·validation PPL의 절댓값·속도를 직접 비교하지 않는다. 약77k/108k는 데이터 노출량 환산값이며 수렴 예산이나 개선 보장이 아니다.

설계 참고: [Guo et al. survey](https://arxiv.org/abs/2111.07624), [Chaudhari et al. survey](https://arxiv.org/abs/1904.02874), [Jiao et al. survey](https://www.techscience.com/cmc/v80n1/57427/html). 서베이는 정보 집계·결합 방식의 설계 참고이며, 위 성능·진단 결과는 수신 GPU 측정에 근거한다.
