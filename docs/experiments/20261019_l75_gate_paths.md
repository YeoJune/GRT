## 1. 이번 실험의 정의와 종료 조건

Gate에는 경로별로 추출한 벡터와 현재 state 정보를 제공하고, 작은 GELU MLP가 사용량을 학습한다. **현재 state 참조는 고정 조건이며 on/off 실험을 하지 않는다.** 비교할 것은 독립 attention 경로, backbone의 별도 gate linear head, candidate 출력 공유의 세 가지다. Candidate의 기존 출력 경로·명칭·write-back은 유지하고, **2번에만 별도 linear head**를 추가한다.

| 단계 | 작업 | 다음 단계 진입 조건 | 현재 상태 |
|---|---|---|---|
| 1 | L75/M20에서 세 경로 비교, state 참조 고정·detach off | 같은 안정화 조건의 학습·사후 결과 확보 | 구현·CPU 검증 완료, GPU 미실행 |
| 2 | 성능·학습 곡선·통계량으로 경로 선정 | 선택과 근거 기록, 차이가 근소하면 복수 유지 | 대기 |
| 3 · 선택 | 선정한 공유 경로의 detach on/off 비교 | 시행/생략 이유와 선택 기록 | 대기 |
| 4 | 최종 조합을 M8/M75로 확장 | 같은 M의 독립 경로 대비 효과·실패·순위 반전 확인 | 대기 |

이 전체를 한 실험으로 관리하며 M20의 best 선정만으로 종료하지 않는다. 이전 초안의 마지막 layer attention 출력 분기와 현재 state 직접 연결 실험은 제거했다. GPU 학습은 Colab/Kaggle에서 사용자가 실행하며 CPU 기능 검사는 연구 결과로 집계하지 않는다.

## 2. 공통 비교 조건

L75, GRT small(D256·6layers·head8·FF1024), M20, router hidden512, 슬롯별 scalar gate[B,M,1], 학습 가능한0 초기 S0, read off, bias0, 동일 WikiText-103 GPT-2 BPE artifact, model/data seed54, FP32, global256, 20k updates로 시작한다. Adam LR5e-4·betas(.9,.999)·decay0·clip.25·cosine·warmup0, BPTT 이전3segments, residual dropout.1·attention dropout0을 유지한다.

안정화 조건은 선행 실험의 종료 방침에 따라 **A(threshold10/coef1e-4) + write dropout0**으로 고정한다. M별 예외 없이 세 경로에서 같은 값을 사용하며, dropout의 장기 효과 검증은 별도로 남긴다.

전체 validation batch10·1k마다 평가·순수 LM NLL/PPL로 각 run의 best checkpoint를 고른다. 최종20k도 별도로 보고하며 test는 후보 선정에 사용하지 않는다. 사후 best checkpoint에서 batch8·warmup3·측정8·horizon4·window0/16/32·random3을 유지한다. 지표는 [공통 사전](20261018_l75_gate_stabilization.md#2-공통-비교-기준)을 따른다.

조건이 달라지면 새 초기화 run으로 실행한다. 같은 seed·동일 backbone 초기화·데이터 artifact를 사용하되, 모듈 구성에 따른 초기화 RNG 소비와 학습 중 dropout 표본이 모두 같다고 표현하지 않는다. 근소한 차이면 후보를 복수 유지하고 필요시 같은 seed 묶음으로 반복한다.

## 3. 구현 경계와 세 경로

### 기존 candidate 경로 유지

```text
X = embedding(segment)                  # [B,N,D]
S = segment-start state                 # [B,M,D]
H = NeoX 마지막 layer의 residual+FFN 합산을 마친 hidden
[Y; C] = 기존 최종 출력 정규화(H)        # C: [B,M,D]
S_next = (1-w) * S + w * C
```

새 candidate head를 만들거나 기존 명칭을 바꾸지 않는다. Token은 모든 layer에서 segment 시작 state만 읽고 중간 candidate register hidden을 K/V로 읽지 않는다. 전체 stack 뒤 write-back 한 번을 유지한다.

**2번 head 입력은 기존 최종 출력 정규화 직전 H의 register 부분이며, 3번은 정규화까지 마친 실제 candidate C다.** 따라서 2번은 C 뒤에 linear를 직렬로 붙이는 것이 아니라 기존 최종 출력 경로의 입력에서 병렬로 분기한다. 마지막 layer attention 출력이나 FFN 중간값은 쓰지 않는다.

### 현재 state를 보는 방식과 MLP는 공통으로 고정

경로별 벡터를 F라 할 때 모든 경로에서 다음 연산을 사용한다.

```text
V = 기존 RegisterAttention(query=F, key=S, value=S)  # D차원 state 요약
G = concat(F, V)                                   # 2D
hidden = GELU(Linear(2D, router_hidden))
raw_logit_i = dot(hidden_i, slot_weight_i) + slot_bias_i
w_i = sigmoid(raw_logit_i)                          # 슬롯별 scalar
```

독립 경로는 원래의 전역 query 하나를 사용하므로 G[B,2D]·hidden[B,512]에서 M개 gate를 출력한다. 2/3번은 슬롯별 F를 query로 사용하므로 G[B,M,2D]·hidden[B,M,512]에서 해당 슬롯의 출력 weight 행을 적용한다. 슬롯별 출력 weight/bias와 hidden 폭을 유지한다. State 참조는 모두 같은 attention 방식이지만 query 내용·개수는 경로에 따라 다르다. 이를 state 정보의 완전한 동일성이나 단일 연결선만의 비교로 표현하지 않는다.

Small에서는 D=256이므로 **MLP 입력512 → hidden512 → 슬롯별 scalar**다. 별도 state 직접 concat, state 평균, gate 전용 정규화·비선형 feature head·유사도 특징·MLP dropout은 추가하지 않는다. Write dropout은 sigmoid write를0으로 만드는 기존 장치로 별도 유지한다.

### P0 / 1번 · independent

```text
X ─ 독립 attention pooling ─ F=u ─┬─ concat(F,V) ─ gate MLP ─ w[1..M]
S ─ RegisterAttention(F,S,S) ─ V ─┘

[X;S] ─ backbone ─ 기존 candidate 출력 C
```

`F=AttentionPool(q_pool,X)`[B,1,D]다. 기존 token embedding 기반 독립 경로와 state attention, 전역 hidden→슬롯별 출력 구조를 그대로 유지한다. 새로운 feature head가 없다.

### P1 / 2번 · separate_head

```text
                                      ┌─ 기존 최종 출력 경로 ─ C
backbone 최종 register hidden H_reg ──┤
                                      └─ gate_head: Linear(D,D) ─ F
S ─────────────────────────────────────── RegisterAttention(F,S,S) ─ V
                                                        concat(F,V) ─ gate MLP ─ w
```

`F=gate_head(H_reg)`[B,M,D]다. **추가 모듈은 이 경로에만 존재하는 D→D linear**이며 bias를 포함한다. 모든 슬롯에 같은 head를 적용하고 출력은 D차원으로 맞춰 3번과 동일한 state attention·MLP 인터페이스를 쓴다. Small에서256→256이며 head만65,792개 파라미터다. Weight std.02·bias0으로 초기화하고 새 정규화·activation·dropout은 넣지 않는다. Candidate C의 계산에는 이 head를 사용하지 않는다.

### P2 / 3번 · candidate

```text
backbone ─ 기존 candidate 출력 C ─ F=C ─┬─ concat(F,V) ─ gate MLP ─ w
S ───────────── RegisterAttention(F,S,S) ─ V
```

Candidate와 같은 출력 경로를 공유하고 실제 C[B,M,D]를 재계산 없이 사용한다. Gate 전용 feature head가 없다. Gate 적용 후 candidate나 갱신된 state를 입력하지 않는다.

### 파라미터·학습 경로의 비교 범위

| 항목 | 1번 | 2번 | 3번 |
|---|---|---|---|
| Gate 정보 출처 | 원래 token embedding의 독립 pooling | 최종 register hidden의 별도 linear | 실제 candidate 출력 공유 |
| 독립 token pooling | 있음 | 없음 | 없음 |
| 추가 gate linear | 없음 | D→D 하나 | 없음 |
| 시작 state 참조 | RegisterAttention | RegisterAttention | RegisterAttention |
| MLP 입력 차원 | 2D | 2D | 2D |
| Gate 계산 시점 | stack 전 | stack 후 | stack 후 |

State attention은 세 경로 모두 유지한다. 공유 경로는 read off일 때 불필요한 token pooling/read head를 만들지 않는다. Read gate를 별도로 켠 경우에도 시작 S에서 read를 먼저 계산하는 계약은 유지한다. 서로 다른 경로의 입력 분포·전역/슬롯별 query·파라미터 수는 달라지므로 전체 gate 설계의 비교로 해석한다. 모델·router·write MLP·추가 gate head의 파라미터 수와 wall time·peak memory를 기록한다.

Small·L75/M20·hidden512·read off 기준이다. 파라미터는 실제 모델에서 집계하고, 연산량은 batch1·segment1회 forward의 attention/linear 입출력 shape로 근사했다. **MAC은 곱셈-덧셈 한 쌍이며 FLOPs는 약2배**다.

| 방식 | 전체 모델 파라미터 | Router 파라미터 | Router forward (M MAC) | Write 경로만 (M MAC) |
|---|---:|---:|---:|---:|
| 1번 독립 attention | 18,682,408 | 1,072,424 | 18.83 | 13.04 |
| 2번 별도 gate linear | 18,211,860 (−2.52%) | 601,876 | 12.01 | 12.01 |
| 3번 candidate 공유 | 18,146,068 (−2.87%) | 536,084 | 10.70 | 10.70 |

세 경로의 write MLP는 모두272,916개이며,2번은3번보다 D→D linear65,792개·약1.31M MAC이 추가된다. 2/3번은 독립 token pooling을 없애지만 M개 슬롯의 state query와 MLP를 계산하므로 파라미터 감소만큼 연산이 줄지는 않는다.

1번은 기존 동작 보존을 위해 read off에서도 read head를 실행한다. Router 합계는 그 파라미터272,916개와 forward 약5.80M MAC을 포함하며, write 열은 해당 연산을 제외한다. 근사 연산량은 공통 backbone·LM head·backward와 bias·softmax·GELU·정규화 등의 소규모 연산을 제외한다. 전체 모델 처리시간·VRAM 개선율이나 GPU 실측 결과로 해석하지 않는다.

## 4. 선택적 detach

첫 비교는 off다. 선정한 공유 경로에서 필요할 때만 비교한다.

```text
2번: F = gate_head(H_reg.detach())
3번: F = C.detach()
공통: V = RegisterAttention(F, S, S)
      w = sigmoid(MLP(concat(F,V)))
```

**2번은 추가 head 앞에서 detach한다.** Head 출력 뒤에서 detach하면 새 gate head까지 학습되지 않으므로 그렇게 구현하지 않는다. Source→backbone gradient만 차단하며 추가 gate head·state attention·MLP는 계속 학습한다. S의 K/V 경로, candidate 자체의 write-back·BPTT 경로는 detach하지 않는다. 따라서 backbone 전체의 모든 gate gradient를 끊는 옵션은 아니다. A 패널티도 같은 연결을 따르므로 source를 통해 전달되는 규제 gradient가 달라진다.

P0의 source detach는 gate 전용 pooling 학습을 끊으므로 거부한다. Logit·hidden scale 증가, 불안정한 학습 곡선, 공유 경로에서의 품질·갱신 붕괴 등을 보고 시행 여부를 정한다. 이 통계만으로 gradient 결합을 원인으로 단정하지 않고 대조 결과를 확인한다. 생략 시에도 이유를 기록한다.

## 5. 지표와 선정 원칙

| 범위 | 확인할 값 | 판단 원칙 |
|---|---|---|
| 전체 validation | best step/NLL/PPL, 최종20k NLL/PPL, 학습 곡선 | 주 품질 기준; 사후 probe와 구분 |
| 학습 통계 | LM/raw R·coef*R·total, raw write 평균·abs logit>20 비율, clipping 전 gradient norm | 기본 W&B는 공통 핵심 패널. 상세 logit·hidden 통계는 사후 분석 |
| 사후 gate | C/O/T·threshold 민감도·window 간 변화, 슬롯 내 gate std, logit 분포 | 고착·문맥 의존성 확인; 큰 std 자체를 목표로 두지 않음 |
| 기억 동작 | candidate 거리와 실제 gated update, 중심화 state/update rank, CKA, reset/swap ΔNLL·lag3 | 표현 통계와 실제 기억 의존성을 함께 확인 |
| 입력·비용 | 경로별 F norm, state 요약 V norm, MLP hidden norm, 추가 head의 weight/bias 통계, 파라미터 수·wall time·peak memory | 경로 차이에 따른 scale·비용을 기록 |

단일 가중합 점수로 자동 선정하지 않고 품질과 진단을 함께 읽고 판단 근거를 기록한다. 근소한 차이면 여러 후보를 유지한다. 단일 seed 차이를 유의한 차이라고 부르지 않고, 사후 여러 window를 독립 학습 반복으로 취급하지 않는다.

2/3번에는 독립 write token pooling attention map이 없으므로 trace 배열을 생략하고 그림에 공유 source임을 표시한다. 임의의0이나 다른 attention으로 대체하지 않는다. 공통 state attention·gate·실제 update·개입 진단은 계속 수집한다. Hidden norm의 상시 학습 로깅은 제거했고 사후 분석에서 전체 분포를 보존한다.

## 6. 실행·전달

기존 Colab/Kaggle 선택 셀을 사용하며 새 조건별 YAML·노트북을 만들지 않는다.

```python
num_registers = 20
write_source = 'independent'  # 다음 run: 'separate_head', 'candidate'
write_detach_source = False
write_dropout = 0.0          # 선행 실험에서 선택한 값으로 세 경로를 고정
write_logit_threshold = 10.0
write_logit_coef = 1e-4
```

Typed Config는 `model.router.write_source`, `model.router.write_detach_source`다. State on/off 설정은 없다. Resolved config와 학습·사후 JSON, run hash로 조건을 확인한다. 기본은 기존1번·detach off다.

CLI 예시는2번이다. Source와 output 경로를 바꾸어 나머지를 실행하며 dropout은 최종 선택값으로 통일한다.

```bash
python scripts/train.py --task wikitext103 --model grt --size small --tokenization gpt2_bpe --budget 20k --runtime colab --set model.segment_len=75 --set model.num_registers=20 --set model.router.write_source=separate_head --set model.router.write_detach_source=false --set model.register.write_gate_bias_init=0 --set model.register.dropout_prob=0 --set model.register.write_logit_threshold=10 --set model.register.write_logit_coef=0.0001 --set rtla.enabled=true --output-dir runs/gate_head_p1_m20 --device cuda
```

노트북은 `setup → prepare_data → preflight → train → report(posthoc=True, download=True, ...)`다. Preflight에서 경로별 microbatch·accumulation·ETA를 측정하되 global256·평가 batch·FP32를 고정한다. 기존 실험 시간을 새 경로의 실측 시간으로 제시하지 않는다. Checkpoint·prepared 데이터는 보존하고 `experiment_results.zip` 하나를 전달한다. 사후 옵션은 [workflow](../20261011_experiment_workflow.md#posthoc-colab)를 따른다.

- [Chaudhari et al., An Attentive Survey of Attention Models](https://arxiv.org/abs/1904.02874): attention query·집계 표현의 구분.
- [Jiao et al., A Comprehensive Survey on Deep Learning Multi-Modal Fusion](https://www.techscience.com/cmc/v80n1/57427/html): 정보 결합 단계의 구분.

서베이는 L75 안정 수렴이나 이번 후보의 우위를 검증한 것이 아니다. 본 실험은 GRT에 맞춘 별도 설계다.

최신 정의의 CPU 검증 대상은 실제 분기점·입력 차원·공통 state attention, 2번에만 존재하는 head, candidate 불변성, detach 후 head 학습, 인과성·prefix/segment 동등성·segment 간 gradient, A·write dropout, 학습 재개·2-worker/serial 대조, checkpoint 사후 JSON·그림, 설정별 run 분리다. 이전 초안의 검사 통과를 최신 정의의 검증으로 대신하지 않는다. GPU 학습·경로 우열·M 전달성은 미검증이다. 후속 실행의 dropout0 고정은 선행 안정화 탐색의 운영 결정이며 장기 우열 판정과 구분한다.

2026-10-19 최신 정의 검증: `test_gate_paths.py`, `test_neox.py`, `test_gate_regularization.py`, `test_register_analysis.py`, `test_posthoc.py`, `test_experiments.py`, `test_memory_analysis.py`의 **140개 검사가 통과**했다. 세 경로의 2-worker CPU/serial 대조와 공유 경로 checkpoint 재개·사후 분석이 포함된다. 별도 원래 HEAD 대조에서1번의 초기 가중치·출력·write dropout RNG가 정확히 일치했다. 노트북 JSON·Python 셀과 문서 링크도 확인했다. 이 결과를 GPU 수렴이나 경로 우열로 해석하지 않는다.
