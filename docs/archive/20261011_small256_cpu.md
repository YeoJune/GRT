# Small D256 직접 CPU 실험 결과

2026-10-11. 공통 small을 D256/6층/8 heads/FF1024로 변경한 뒤 공개 인터페이스를 직접 호출했다.
기존 D32 CPU preset을 사용하지 않았고 small backbone의 6층과 D256을 유지했다.

## 변경된 small 설정

- `configs/wikitext_small.yaml`: d_model=256, d_ff=1024(4D), layers=6, heads=8, head dimension=32.
- RoPE=0.25/base10000, parallel residual, tied head. GRT는 intermediate/read off를 유지했다.
- WikiText full V267735에서 공통 backbone 73279232, RMT 전체 73281792, GRT 전체 74343956 parameters.
- Remember V128에서 공통 backbone 4771840, RMT 전체 4780032, GRT 전체 5864768 parameters.

## 호출 경로와 재실행

`scripts/check_small.py`가 `load_config → validate_config → create_model → evaluate → run → load_checkpoint/restore_model → evaluate/generate`를 직접 호출한다.
초기 모델, validation으로 선택된 best, 최종 last를 따로 평가하고 masked slot/생성 출력을 기록한다.
새 실험 폴더를 지정해 다음과 같이 재실행한다.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python scripts/check_small.py --output-dir runs/small256_cpu_recheck --threads 1 --remember-steps 60 --lm-steps 6
```

이번 결과는 로컬 집계 JSON `runs/small256_cpu/results.json`, 각 실험의 `resolved_config.yaml`, `metadata.json`, `cpu_experiment.json`, `metrics.jsonl`, best/last checkpoint에 보존했다. `runs/`의 원본 산출물은 푸시에서 제외하며 이 문서의 결과 요약과 재실행 스크립트만 저장소에 포함한다.

## Remember: 실제 과제 데이터

모델별 인코더·디코더 4개 조건. fact 1개, key/value 길이1, segment4, memory32.
FP32/CPU 1 thread, batch8/global8, 60 updates(480 sample 처리), train256/validation64/test128.
model seed/data seed=54, test는 별도 seed 생성이다. 유한한 key/value 조합은 split 사이에 중복될 수 있다.
인코더 query는 `[key,GEN101,MASK103,MASK103]`와 value/EOS slot CE, 디코더는 기존 next-token CE/생성 평가다.
기존 Remember AdamW(lr3e-4, decay0.001, beta2=0.999), value clip1, linear scheduler(warmup6/총120)를 유지했다.
CPU를 위해 batch/sample/update 예산만 줄였다. loss는 test128 전체 평균이며 아래 최종 값은 **last.pt, step60**이다.

| 모델 | 버전 | 초기 CE | 최종 CE | 최종 EM | value 정확도 | EOS 정확도 | 학습 호출 wall time |
|---|---|---:|---:|---:|---:|---:|---:|
| GRT | encoder | 4.8619 | 2.1874 | 0.00% | 0.00% | 100.00% | 26.8s |
| RMT | encoder | 4.7585 | 2.1945 | 0.00% | 0.00% | 100.00% | 44.6s |
| GRT | decoder | 4.9705 | 1.5459 | 7.03% | 7.03% | 100.00% | 30.4s |
| RMT | decoder | 4.9096 | 1.5367 | 7.03% | 7.03% | 100.00% | 53.2s |

인코더 두 모델은 test128 전부에서 value/EOS 두 slot 모두 `[102,102]`를 출력했다. 예를 들어 target `[10,102]`에도 `[102,102]`였다.
Loss 감소를 value retrieval 성공으로 볼 수 없다. 디코더 두 모델도 test128 모두에서 `[5,102]`로 같은 출력을 냈다.
EM 7.03%(9/128)는 value가5인 sample9개에서만 맞은 값이며, 균등 추측 기준6.25%와 가깝다.
60 update만으로 retrieval 학습이나 수렴을 확인하지 못했다. 동일 MASK slot의 구분 어려움과 짧은 학습 예산은 추가 분석 후보이며 원인은 확정하지 않았다.
마스크·read policy·optimizer·학습 예산을 결과에 맞춰 추가 조정하지 않았다.

현재 Remember best 선택 기준은 validation EM의 엄격한 개선이다. 네 조건 모두 **best는 step20**에 남았다.
따라서 최종 step60과 best를 혼동하면 안 된다. best test 결과는 다음과 같다.

| 모델 | 버전 | 선택 step | best test CE | best test EM |
|---|---|---:|---:|---:|
| GRT | encoder | 20 | 2.5026 | 0.00% |
| RMT | encoder | 20 | 2.5014 | 0.00% |
| GRT | decoder | 20 | 1.9071 | 6.25% |
| RMT | decoder | 20 | 1.8855 | 6.25% |

## LM: full-vocabulary 합성 스트림

**실제 WikiText-103 데이터/논문 PPL 결과가 아니다.** 작업 공간에 원본 파일이 없어서 인터페이스를 검증할 합성 corpus를 생성했다.
원래 준비 함수로 word vocabulary267735를 구성했다. train은 반복되는 `alpha beta gamma <unk>` 600줄과 unique267730 단어, validation/test는 반복80줄이다.
생성 manifest의 dataset 식별자를 `synthetic CPU interface check; NOT WikiText-103`으로 명시했다.
검증/시험 문장은 같은 반복 패턴이므로 일반화 지표로 해석하지 않는다.

D256/6층/8 heads/FF1024, segment150, memory10, BPTT 이전3, dropout0.1, attention dropout0, FP32는 유지했다.
Adam lr2.5e-4/betas0.9,0.999/eps1e-8/decay0, cosine/warmup0, norm clip0.25도 동일하다.
CPU 예산은 microbatch1/accumulation1/**global batch1**, 6 updates로 줄였다. 승인된 본 실험 global60/200000 updates와 구별한다.
두 모델 모두 train target900, test target399를 처리했다. best와 last는 모두 step6이다.

| 모델 | 초기 NLL | 최종 NLL | 최종 합성 PPL | score_kind | 학습 호출 wall time |
|---|---:|---:|---:|---|---:|
| GRT | 12.6540 | 8.0491 | 3130.87 | teacher_forced_noncausal | 22.5s |
| RMT | 12.6489 | 8.0091 | 3008.06 | autoregressive | 22.2s |

vocabulary를 작은 toy 크기로 줄이지 않고 실제 full softmax와 optimizer/checkpoint/state carry를 실행했다.
GRT와 RMT의 score_kind가 다르므로 위 PPL 차이를 동일 causal 조건의 모델 우열로 해석하지 않는다.
wall time은 run의 학습·주기 평가·checkpoint I/O·최종 평가를 포함한다. 초기/추가 checkpoint 진단 시간은 제외하며 엄밀한 속도 benchmark가 아니다.

## 옵션 직접 호출과 검사

학습된 small GRT에서 nonzero incoming state를 주고 `cell`을 호출해 future token/prefix 길이를 변경했다. read off 유지.
원래 intermediate에서는 이전 위치 hidden이 변했고, fixed_state로 전환하면 미래 token 변경에 불변이었다.

- intermediate 미래 변경: max |Δhidden| = 0.026863752.
- fixed_state 미래 변경: max |Δhidden| = 0.0.
- fixed_state 가변 길이 prefix: max |Δhidden| = 8.34465027e-07; FP32 tolerance 내 일치.

값은 로컬 옵션 검사 JSON `runs/small256_cpu/causal_option_check.json`에 있다.
기존 새 모델 CPU 회귀 검사 `pytest -q tests/test_neox.py -k "not distributed"`: **16 passed**.
Python compile 및 `git diff --check` 통과. GPU 실행과 실제 WikiText 학습은 수행하지 않았다.
