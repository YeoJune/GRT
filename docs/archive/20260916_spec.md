## 1. 적용 범위와 우선순위

이 문서는 기존 documents/spec_260608.md와 후속 업무 지시서를 통합하고, 2026-09-16에 합의한 변경을 반영한다. 새 구현에서 충돌하는 사항은 이 문서를 우선한다. 기존 문서는 설계 이력으로 보존한다.

이번 구현 범위:

1. Gated Register Transformer(GRT).
2. 독립적으로 구현한 Recurrent Memory Transformer(RMT) 비교 모델.
3. Copy, Reverse, Associative Retrieval 합성 과제.
4. 공통 데이터, 학습, 평가, 체크포인트, 로깅.
5. GRT 전용 RTLA Light.
6. 학습 길이 평가와 zero-shot 길이 확장 평가.

이번 범위에 포함하지 않는 항목:

- 자연어 데이터셋, PG-19, 외부 tokenizer, 자연어 자기회귀 생성.
- Entity tracking, in-context arithmetic, Vanilla Transformer 비교.
- 본격적인 ablation 실험, 자동 하이퍼파라미터 탐색.
- 분산 학습, 스트리밍 추론 API, truncated BPTT.

이들은 후속 연구 범위다. 이번 명세의 선택 옵션은 후속 실험을 가능하게 하되, 구현 완료를 위해 모든 조합을 실험할 필요는 없다.

연구 가설은 고정 크기 메모리의 읽기·쓰기 제어가 기억 유지와 갱신에 기여하는지 확인하는 것이다. 게이트 분포의 차이만으로 의미적 역할 분화나 장기기억을 입증했다고 판단하지 않는다.

## 4. 합성 데이터의 정확한 계약

### 4.1 공통 토큰과 배치

모든 위치는 0-based이며 구간은 Python slice와 같은 [start, end)다.

| ID | 의미 | 사용 위치 |
|---|---|---|
| 0 | PAD | 일반 인터페이스의 padding용; 본 벤치마크에서는 사용하지 않음 |
| 1 | SEP | Retrieval의 key와 value 사이 |
| 2 | QUERY | Retrieval의 마지막 질의 위치 |
| 3 | OUT | Copy/Reverse 출력 placeholder |
| 4..1023 | content | target, key, value, noise |

V=1024는 예약 토큰을 포함한다. 외부 tokenizer를 사용하지 않고 정수 ID를 직접 생성한다.

- content와 noise는 4..1023에서 균등 샘플링한다.
- Copy/Reverse target은 독립 복원추출한다. 같은 토큰이 여러 번 나와도 유효하다.
- noise에 예약 토큰은 등장하지 않는다. noise가 우연히 target/value와 같은 ID를 갖는 것은 허용한다.
- 샘플 전체를 먼저 noise로 채운 뒤 지정된 target/fact/query/output 위치를 덮어쓴다.
- labels는 전체 -100으로 초기화하고 정답 위치만 채운다.
- 정답 출력값을 OUT 위치나 QUERY 뒤의 입력에 삽입하지 않는다.
- 각 샘플의 길이는 L=T*N, N=128이다. 정확히 T개 세그먼트로 reshape/split한다.
- attention_mask는 본 벤치마크에서 모두 true이다.
- 한 배치에는 동일 task·동일 T만 포함한다. 혼합 길이 batch는 이번 범위 밖이다.

공통 Batch:

| 필드 | dtype / shape | 계약 |
|---|---|---|
| input_ids | int64 [B,L] | 0 ≤ ID < 1024 |
| attention_mask | bool [B,L] | true=유효, false=padding |
| labels | int64 [B,L] | 해당 위치 logit의 정답 ID 또는 -100 |

task, split, sample_id 등의 메타데이터는 데이터셋/평가 결과에서 관리한다. 모델 입력으로 전달하지 않는다. label shift를 trainer나 모델에서 추가로 하지 않는다.

### 4.2 Copy

- target: a[0..19], 총 20개.
- 첫 세그먼트의 local [0,20)에 target을 입력한다.
- 마지막 세그먼트의 local [108,128)에 OUT 20개를 입력한다.
- 동일 출력 위치의 labels에 a[0..19]를 지정한다.
- 나머지 모든 위치는 noise이며 labels=-100이다.
- 학습 T=4. 길이 확장 평가는 T=10,20.

| 분할 | T | L | target 입력 범위 | 출력 및 정답 범위 |
|---|---:|---:|---|---|
| train / validation / test 기본 | 4 | 512 | [0,20) | [492,512) |
| test 확장 | 10 | 1280 | [0,20) | [1260,1280) |
| test 확장 | 20 | 2560 | [0,20) | [2540,2560) |

샘플당 유효 labels 수는 정확히 20이다. 마지막 세그먼트의 첫 108토큰도 noise다.

### 4.3 Reverse

입력 배치, 길이, 예약 토큰, loss 위치는 Copy와 동일하다. labels만 역순으로 지정한다.

- output local 108+j의 정답 = a[19-j], j=0..19.
- 학습 T=4, 확장 평가 T=10,20.
- 샘플당 정답 토큰 수 = 20.
- Copy와 Reverse는 별도 모델 run으로 학습한다. 하나의 모델에 task ID를 넣어 멀티태스크 학습하지 않는다.

### 4.4 Associative Retrieval

- 서로 다른 key 4개를 content 범위에서 비복원추출한다.
- value 4개는 content 범위에서 독립 복원추출한다.
- value의 중복, key와 value의 ID 일치는 허용한다. key만 고유하면 mapping은 명확하다.
- first segment local [0,12)에 다음을 배치한다:
  [k0, SEP, v0, k1, SEP, v1, k2, SEP, v2, k3, SEP, v3].
- query index q는 0..3에서 균등 선택한다.
- 마지막 세그먼트 local 126에 kq, local 127에 QUERY를 넣는다.
- labels[L-1]=vq. 다른 labels는 모두 -100.
- 마지막 QUERY 위치의 logit이 value를 예측한다. 입력에 답을 추가하지 않으며 L을 늘리지 않는다.
- 학습 T=5, 확장 평가 T=15,30.

| 분할 | T | L | facts 입력 범위 | query key | QUERY 및 정답 위치 |
|---|---:|---:|---|---:|---:|
| train / validation / test 기본 | 5 | 640 | [0,12) | 638 | 639 |
| test 확장 | 15 | 1920 | [0,12) | 1918 | 1919 |
| test 확장 | 30 | 3840 | [0,12) | 3838 | 3839 |

샘플당 정답 토큰 수는 정확히 1이다. query 하나로 평가하며, num_queries를 기존 코드에서 상속하지 않는다.

### 4.5 생성의 재현성과 분할

운영 기본값:

- data_seed=20260916.
- validation_samples=1024.
- test_samples=4096, 각 평가 길이에 동일하게 적용.
- train은 결정적 sample_id 기반으로 필요한 만큼 생성한다.
- train / validation / test는 서로 다른 RNG namespace를 사용한다.
- 동일 task·split·sample_id는 모델 종류, batch size, worker 수, 모델 초기화 seed에 영향을 받지 않는다.

구현 권장 규칙: hashlib.sha256으로 data_seed/task/split/sample_id/component를 UTF-8 인코딩하여 hash하고, 앞 8바이트를 little-endian 정수로 해석한 뒤 2**63으로 나눈 나머지를 torch.Generator의 seed로 사용한다. Python hash()는 사용하지 않는다.

- component="payload"는 target/facts/query index 생성용. 길이 T를 seed에 포함하지 않는다.
- component="noise:T"는 각 길이의 noise 생성용.
- 같은 test sample_id는 확장 길이들에서 동일 payload와 query를 사용한다.
- 데이터 RNG는 모델·dropout RNG와 분리한다.
- 복원추출이므로 split 간 토큰이나 payload의 우연한 일치까지 금지하지 않는다. 별도의 sample namespace와 독립 생성으로 데이터 분할을 정의한다.

## 5. 모델 공통 인터페이스

~~~python
@dataclass
class ModelOutput:
    logits: Tensor  # [B,L,V]

def forward(
    self,
    input_ids: Tensor,
    attention_mask: Tensor | None = None,
) -> ModelOutput:
    ...
~~~

- labels/loss/trace를 공통 ModelOutput에 넣지 않는다.
- attention_mask=None은 모든 토큰 유효로 처리한다.
- 기본 forward는 모든 토큰 위치의 logits를 반환한다.
- 모델은 입력에 대응하는 출력 위치를 유지한다.
- 매 forward마다 새 샘플의 초기 메모리로 시작한다. 서로 다른 배치 사이 상태를 전달하지 않는다.
- 모델 내부에서 N 단위로 분할하고, 모든 세그먼트 사이 상태를 detach 없이 전달한다.
- input_ids는 rank 2, L>0, L%N==0이어야 한다.
- 본 구현은 all-true attention_mask만 지원한다. false가 있으면 명확한 ValueError를 내며 조용히 무시하지 않는다. 실제 padding 지원은 후속 확장이다.
- 반환 logits에는 softmax를 적용하지 않는다.
- factory는 name="grt" 또는 "rmt"만 지원하며 잘못된 이름은 에러다.

임베딩:

- token embedding: [V,D], Normal(0,0.02).
- token local position embedding: [1,N,D], Normal(0,0.02).
- 매 세그먼트에서 local position을 0..127로 재사용한다.
- 전역 segment position embedding은 사용하지 않는다. 학습 길이 밖의 인덱스를 clamp하는 구현도 사용하지 않는다.
- bias 없는 LM head와 token embedding을 동일 Parameter로 묶는다.
- 이번 실험에서는 tie_word_embeddings=true를 검증한다.

## 6. GRT 구현

### 6.1 기본 설정과 상태

- S0: learnable Parameter [1,M,D], zero initialization.
- batch에 expand하여 초기화한다. 상태를 in-place 수정하지 않는다. clone 사용은 허용하되 expand 자체가 gradient를 끊는다고 설명하지 않는다.
- 별도 register ID embedding은 이번 기준 모델에 넣지 않는다.
- conditional_read=false.
- write_dropout=0.0.
- write_gate_bias_init=-2.0.
- router pool_nhead=4, mlp_hidden=512. large에서도 이 라우터 기본값은 유지한다.
- S, candidate는 부동소수 실수 벡터이며 값 범위를 clamp하지 않는다.

### 6.2 Global Router

입력 X [B,N,D], S [B,M,D].

1. learnable q_pool [1,1,D]로 X에 multi-head attention pooling:
   X_rich [B,1,D], alpha [B,N].
2. Q=X_rich, K=V=S인 register cross-attention:
   C [B,1,D].
3. G=concat(X_rich,C), [B,2D].
4. 독립 MLP 두 개:
   Linear(2D,512) → GELU → Linear(512,M).
5. sigmoid 후 R,W [B,M,1].

Attention은 nn.MultiheadAttention(batch_first=True, dropout=0.0) 기준으로 구현한다. q_pool은 Xavier uniform 초기화한다. R 마지막 bias=0, W 마지막 bias=-2.0. 나머지 linear/attention 초기화는 PyTorch 기본값을 사용하고 실행 버전을 기록한다. bias만으로 sigmoid 출력이 정확히 0.5/0.119가 된다고 가정하지 않는다.

Write dropout이 켜진 경우 학습 시 [B,M,1]의 독립 Bernoulli mask를 적용하여 W의 logit을 -inf로 만든다. 다음과 같다.

- 해당 슬롯 W=0.
- 기존 상태를 보존.
- S 자체를 0으로 만들지 않음.
- inverted-dropout rescaling 없음.
- 평가에서는 dropout 비활성.

### 6.3 Read와 ALU

- conditional_read=true: S_read=R*S.
- conditional_read=false: S_read=S.

Read가 Off일 때 router는 진단 목적으로 R을 산출할 수 있지만 ALU나 loss 계산에 사용하지 않는다. read MLP는 과제 loss로 학습되지 않는다. 공유 router 표현의 변화로 R 값이 변할 수 있으므로 R 변화 자체를 학습된 읽기 전략으로 해석하지 않는다. config/trace에 read_active=false를 기록한다.

ALU 입력은 concat(X,S_read), shape [B,N+M,D]다.

- nn.TransformerEncoderLayer.
- batch_first=true, norm_first=true.
- activation=gelu, dropout=0.1.
- 양방향 self-attention, causal mask 없음.
- 앞 N개 출력은 Y, 뒤 M개 출력은 candidate.
- encoder layer마다 독립 Parameter를 가진다. 레이어 간 weight sharing은 하지 않는다.

이 attention은 병렬 복원 과제를 위한 선택이다. 정답이 출력 placeholder에 입력되지 않으므로 teacher forcing에 의한 정답 누출은 없다. 일반적인 causal LM 성능으로 해석하지 않는다.

### 6.4 Write-back

candidate를 C_t라 표기한다. 과거 문서의 delta_s/ΔS는 더할 증분이 아니라 이 후보 상태다. 새 코드에서는 candidate 또는 s_candidate라는 이름을 권장한다.

S_next = (1-W)*S + W*C_t

추가 forget gate, decay, state normalization은 넣지 않는다. no-detach BPTT와 공통 gradient clipping을 사용한다.

전체 Jacobian은 gate와 candidate의 상태 의존성을 포함한다. 상태를 vectorize하고 W를 D차원에 broadcast하면:

J = diag(1-W) + diag(C_t-S) J_W + diag(W) J_C

diag(1-W)는 직접 보존 경로다. W→1이어도 candidate와 router 경유 gradient가 반드시 사라지는 것은 아니다. 이 수식만으로 gradient explosion 방지가 보장된다고 주장하지 않는다.

세그먼트의 연산 길이는 N+M=160이다. 고정 N,M에서 과거 세그먼트 수와 무관하게 세그먼트별 연산량이 일정하다는 뜻이며 전체 시퀀스 계산량은 T에 비례한다. full BPTT와 전체 logits 보관 때문에 학습 메모리나 현재 forward의 전체 메모리가 L과 무관하다는 뜻은 아니다.

## 7. RMT 구현

RMT는 독립 Transformer 백본으로 구현한다. 원 논문의 메모리 전달 패턴인 앞쪽 read memory와 뒤쪽 write memory를 따른다. 이번 비교는 양방향 backbone을 쓰는 합성 과제용 구현이며, 특정 pretrained causal RMT의 완전한 재현으로 표기하지 않는다.

- memory 수 M=32.
- learnable mem0 [1,M,D], Normal(0,0.02).
- learnable read_marker, write_marker 각각 [1,1,D], Normal(0,0.02).
- token embedding, local token position, tied LM head는 공통 사양을 따른다.
- encoder는 GRT ALU와 동일 layers/heads/D/d_ff/dropout/activation/norm 설정을 사용하되 별도 구현·파라미터다.

세그먼트 처리:

~~~python
seq = torch.cat(
    [mem + read_marker, x + pos_emb, mem + write_marker],
    dim=1,
)
out = encoder(seq)
token_out = out[:, M:M+N]
mem = out[:, M+N:M+N+M]
logits_t = lm_head(token_out)
~~~

- mem은 다음 세그먼트로 detach 없이 전달한다.
- gated write-back, router, conditional read는 없다.
- backward path가 마지막 출력에서 이전 세그먼트 memory로 연결되어야 한다.
- mem은 각 forward에서 mem0로 다시 초기화한다.
- 연산 길이는 N+2M=192다.
- GRT와 RMT의 연산량/파라미터 수가 다름을 결과에 명시한다.

## 8. 모델 크기 및 비교 조건

| 크기 | Layers | Heads | D | d_ff | N | M | V |
|---|---:|---:|---:|---:|---:|---:|---:|
| small | 4 | 4 | 256 | 1024 | 128 | 32 | 1024 |
| large | 8 | 8 | 512 | 2048 | 128 | 32 | 1024 |

소형 백본은 tied embedding을 포함해 대략 3.4M, 대형 백본은 대략 25.7M 규모이며, 모델별 router/position/memory 파라미터에 따라 총수가 달라진다. 이 근삿값을 실행 결과로 사용하지 않는다.

- total_params와 trainable_params는 실제 Parameter에서 계산하여 기록한다.
- tied weight를 두 번 세지 않는다.
- 비교는 동일 백본 사양 기준이다. parameter-matched라고 부르지 않는다.
- 각 모델·각 과제·각 크기를 별도로 학습한다.
- data_seed와 sample 순서, optimizer, effective batch, max_steps, eval 표본은 동일하게 적용한다.
- 운영 기본 model_seed=1234. 본 결과는 가능하면 [1234,2345,3456]으로 반복하고 평균·표준편차를 보고한다. 1회 결과는 단일 seed라고 명시한다.

## 10. 공통 학습·평가

### 10.1 Loss와 metric

loss는 labels!=-100인 위치만 대상으로 하는 cross entropy다. logits를 float32로 변환해 loss를 계산한다.

- CE = 전체 유효 정답 위치의 negative log likelihood 합 / 유효 정답 토큰 수.
- token_accuracy = 맞힌 정답 토큰 수 / 전체 정답 토큰 수.
- exact_match = 모든 정답 위치를 맞힌 샘플 수 / 전체 샘플 수.
- Retrieval은 정답이 하나여서 token accuracy와 exact match가 같다.
- batch별 평균을 무조건 평균하지 않고 합계와 count를 누적한다.
- 유효 labels가 0개인 batch는 오류다.
- perplexity=exp(CE)는 보조 지표로만 기록한다. 자연어 LM perplexity로 해석하지 않는다.

Copy/Reverse 출력은 OUT 20개를 동시에 argmax한다. beam search, autoregressive rollout, teacher forcing을 사용하지 않는다.

### 10.2 학습

- 모델.train(), optimizer.zero_grad(set_to_none=True).
- effective batch = microbatch * grad_accum_steps.
- accumulation 시 effective batch 전체 정답 토큰 기준으로 loss scale을 맞춘다.
- loss backward → unscale(fp16) → clip → optimizer step → scheduler step.
- scaler가 overflow로 optimizer step을 건너뛴 경우 scheduler와 global optimizer step을 진행하지 않는다. skip을 로그에 남긴다.
- 검증·RTLA·checkpoint 주기는 완료된 optimizer update의 1-based global_step 기준이다.
- 정상 종료 시 마지막 update가 주기 경계가 아니어도 validation과 last checkpoint를 저장한다.
- loss/grad가 비유한 경우 진단 정보를 남기고 중단한다. silent retry로 숨기지 않는다.
- 검증은 eval()+no_grad()로 실행하고 이전 training 상태를 복원한다.
- 검증/분석은 학습 sample stream이나 모델 학습 RNG를 소모하지 않도록 독립 데이터 및 RNG 보존을 적용한다.

검증 loss가 0.05 이하라는 이유만으로 자동 조기 종료하지 않는다. 동일 update 예산으로 학습하면서 최초 목표 도달 step을 별도로 기록한다. best checkpoint는 학습 길이 validation CE 최솟값 기준이며 test 결과로 선택하지 않는다.

### 10.3 Checkpoint

각 run의 최소 산출물:

- resolved_config.yaml
- metrics.jsonl
- best.pt / last.pt
- 주기 checkpoint: step_XXXXXX.pt
- evaluation.json (길이별 성능)
- rtla/ (GRT 분석이 켜진 경우)
- 실행 metadata: Git commit, Python/PyTorch/CUDA 버전, GPU, 실제 파라미터 수, dtype, seed

checkpoint에는 schema/spec version, model config, model state, optimizer/scheduler/scaler state, global_step, best validation loss, 누적 학습 시간, 다음 train sample_id, Python/NumPy/Torch/각 CUDA RNG 상태를 저장한다. 저장은 임시 파일 작성 후 atomic replace를 사용한다.

재개 검증은 dropout이 켜진 작은 CPU fixture에서 중단 없는 실행과 동일한 다음 sample 및 다음 update를 재현하는 것으로 수행한다. GPU에서는 backend 결정성 한계를 기록한다.

### 10.4 평가와 성능 측정

최종 best checkpoint로 각 과제의 기본 길이 및 두 확장 길이를 평가한다. 확장 길이로 fine-tuning하지 않는다. 길이별 동일 test sample_id 집합을 사용한다.

기록 항목:

- task, model, size, seed, T, L, sample 수.
- masked CE, token accuracy, exact match.
- 학습 길이에서 CE≤0.05에 최초 도달한 validation step 및 시간.
- input tokens/sec, samples/sec.
- peak allocated GPU memory, batch size, precision.
- 실제 total/trainable parameter 수.

Throughput은 별도의 inference 측정 구간에서 계산한다.

- model.eval(), inference_mode().
- 데이터 생성·CPU→GPU 전송·RTLA·파일 저장·W&B 업로드는 timed region 밖.
- 기본 warmup 10회, 측정 50회.
- GPU는 측정 시작 전과 종료 후 synchronize.
- peak memory는 warmup 후 reset_peak_memory_stats로 초기화.
- 토큰 처리량은 B*L*측정 횟수 / 경과시간. supervised token 수로 바꾸지 않는다.
- GRT와 RMT의 internal memory token 수 차이는 별도 설명한다.
- CPU는 peak GPU memory를 null로 기록한다.
- 더 작은 batch로 평가해야 할 경우 두 모델을 동일 batch로 다시 측정한다. OOM을 숨기지 않는다.

full logits 출력 비용도 이번 공통 API의 실제 비용에 포함한다. 미래의 logits 최적화와 결과를 혼합하지 않는다.

## 11. RTLA Light

### 11.1 연결 방식

GRT의 공통 forward는 ModelOutput만 반환한다. 분석용 별도 메서드를 둔다.

~~~python
def forward_with_trace(
    self,
    input_ids,
    attention_mask=None,
) -> tuple[ModelOutput, TraceBuffer]:
    ...
~~~

동일 내부 forward 구현을 공유하여 계산 경로가 달라지지 않게 한다. eval 상태에서 두 메서드의 logits는 같아야 한다.

trainer는 선택적 on_evaluate(model, global_step) callback만 호출한다. CLI에서 GRT 분석 callback을 연결한다. callback은 별도의 고정 validation probe batch를 사용하고 eval/no_grad로 실행한 뒤 원래 mode를 복원한다. 이 설계로 학습 dropout이 분석 결과에 섞이지 않게 한다.

### 11.2 통계 정의

모든 통계는 갱신 전 상태 S_t 기준이다. norm/distance는 .float() 변환 후 계산하고 그래프를 만들지 않는다.

| 신호 | 배치 집계 후 shape | 계산 |
|---|---|---|
| r_gates | [T,M] | mean_b R[b,t,m] |
| w_gates | [T,M] | mean_b W[b,t,m] |
| s_norms | [T,M] | mean_b norm(S[b,t,m,:].float(),2) |
| update_distances | [T,M] | mean_b norm(candidate-S,2), 두 항 모두 FP32 |
| attn_weights | [T,N] | attention head 평균 후 batch 평균 |

norm(mean_b S)로 계산하지 않는다. 샘플별 norm을 먼저 계산한다. 과거 pred_error 명칭은 metadata에 설명하되 새 저장 키는 update_distances를 사용한다.

- 통계 계산 후 detach().cpu()하여 float32 NumPy로 직렬화한다.
- training activation 전체나 원본 [B,T,M,D] 상태를 저장하지 않는다.
- np.savez_compressed로 저장한다.
- 파일명에 step/task/T를 넣어 덮어쓰기를 막는다.
- metadata: batch sample_ids, read_active, N,M,D,T,checkpoint/global_step,spec version.

### 11.3 패널

- A: R/W를 분리한 [T,M] heatmap. R은 Off일 때 "inactive read head"라고 표시.
- B: 레지스터별 W와 state norm의 시간 변화. 서로 다른 단위는 분리 axis 또는 분리 subplot으로 표시.
- C: pooling attention [T,N] heatmap.
- D: update distance [T,M] heatmap.

배치 평균을 기본 시각화로 사용한다. 선택적인 개별 sample 분석은 허용하지만 평균 결과와 명확히 구분한다.

mean R/W, 슬롯별 mean W, 슬롯 간 std 등은 진단값이다. 낮은 W를 바로 dead register로 분류하지 않는다. threshold만으로 long-term/working/scratch 확정 라벨을 붙이지 않는다. 높은 W 경고도 정보 붕괴의 입증으로 취급하지 않는다.

### 11.4 W&B와 로컬 저장

- wandb.enabled=false여도 학습·평가·로컬 trace·PNG가 완전히 동작해야 한다.
- W&B는 선택 의존성이고 켜진 경우에만 import/init한다.
- run 초기화는 CLI에서 한 번.
- 같은 global_step의 metrics는 가능한 한 하나의 log payload로 묶는다.
- scalar 예: train/loss, train/lr, train/grad_norm, val/loss, val/token_accuracy, val/exact_match, rtla/mean_w.
- 패널은 명시적인 축·범례를 가진 PNG/wandb.Image로 전송한다.
- W&B custom chart용 long-form Table은 timestep/register/read/write/state_norm/update_distance 열을 제공한다. attention Table은 timestep/token_position/weight 열을 사용한다.
- 클라우드 전용 dashboard가 없어도 저장된 데이터로 동일한 그림을 만들 수 있어야 한다.
- W&B 실패 시 로컬 결과를 보존하고 경고를 기록한다.
- trace 계산과 전송 비용은 0이 아니다. 주기와 batch 크기로 제한하고 throughput 측정에서 제외한다.

## 12. 개발 단계와 검증 기준

실험 Phase A/B/C와 개발 단계를 구분한다.

### 개발 1: 공통 계약과 데이터

구현: config, interface, data, metrics.

필수 검증:

- 각 task/길이의 L, 정확한 위치, 정답 개수.
- input 출력 위치에 정답을 넣지 않는다는 구조적 규칙.
- Reverse 정답 순서.
- Retrieval key 고유성 및 query 정답 일치.
- noise는 content 범위만 사용.
- 동일 sample_id의 결정성, batch/worker/model RNG와 독립성.
- 데이터 oracle로 labels를 계산해 생성 결과와 일치 확인.
- 틀린 config, 길이, 토큰 범위에 대한 오류.
- masked CE/token accuracy/exact match의 작은 수작업 예제.

### 개발 2: 모델

구현: 독립 GRT/RMT, factory.

필수 검증:

- 두 모델 공통 [B,L,V] 출력 및 finite logits.
- tied embedding은 동일 Parameter 객체.
- 다른 forward 호출 간 상태 누출 없음.
- local position embedding 적용.
- GRT ALU 길이 N+M, RMT 길이 N+2M.
- full BPTT: 마지막 세그먼트 loss가 이전 상태에 gradient를 전달.
- GRT W=0/1의 write-back 결과.
- read Off에서 read head만 바꿔도 logits 불변; On에서는 read 경로가 연결됨.
- S0 zero/learnable, dropout 0 및 강제 dropout 경계 동작.
- RMT 뒷부분 memory 출력이 다음 앞/뒤 memory 입력에 실제 전달됨.
- 잘못된 rank/길이/padding 지원 요청에 오류.

작은 fixture를 사용해 CPU에서 수행한다. shape 통과를 기억 과제 수렴의 증거로 해석하지 않는다.

### 개발 3: 학습·평가·복원

- 두 모델이 같은 trainer/evaluator로 실행.
- 작은 고정 batch를 overfit할 수 있는 smoke 실험.
- label이 없는 위치는 loss에서 제외.
- accumulation, scheduler/global_step, final checkpoint 처리.
- checkpoint 재개와 factory를 통한 RMT/GRT 복원.
- eval/RTLA 후 train mode 및 RNG 복원.
- W&B 없이 end-to-end 실행.
- 평가 집계가 batch 분할에 영향을 받지 않음.

### 개발 4: 분석 및 실행 문서

- trace shape, FP32 dtype, batch 평균 공식, 갱신 전 상태 검증.
- 일반 forward와 trace forward의 eval logits 동일성.
- PNG/NPZ 생성.
- read Off 시 비활성 표시.
- README의 두 모델 CLI를 실제 smoke 실행으로 검증.
- 기존 패키지와 새 모듈의 이름 충돌 및 stale import 제거.

## 13. 실험 단계

### Phase A: small RMT

세 과제를 각각 학습하여 데이터/학습 기반을 확인한다.

- 학습 길이 validation CE≤0.05를 목표로 한다.
- token accuracy와 exact match를 함께 확인한다.
- 10/20 또는 15/30세그먼트 결과는 zero-shot 일반화 성능으로 보고한다.
- 수렴하지 않으면 데이터 oracle, 누출, 메모리 전달, loss mask, gradient, optimizer를 먼저 점검한다.
- 목표 실패를 이유로 정답을 입력에 넣거나 noise 구간을 몰래 줄이지 않는다.

### Phase B: small GRT

동일 과제·데이터·예산으로 GRT를 학습한다.

- read Off, write dropout 0.
- 수렴 속도, 기본/확장 길이 성능, memory/throughput을 RMT와 비교한다.
- RTLA로 슬롯별 갱신 양상을 관찰한다.
- read 활성 해석 및 의미적 역할 분화 주장에 주의한다.

### Phase C: large GRT와 large RMT

대형 사양에서도 두 모델을 모두 실행한다.

- 동일 비교 조건 유지.
- 고정된 확장 길이 성능을 우선 보고한다.
- 추가 길이 sweep은 별도 탐색 실험으로 표시한다.
- 최대 성공 길이를 보고할 때 sweep 후보 T와 성공 임계치(예: exact match 기준)를 실행 전에 정한다. 고정 두 길이만으로 최대 한계를 확정하지 않는다.
- 여러 seed 결과, 실제 파라미터 수, hardware/dtype, update 예산을 포함한다.

최종 비교 표의 한 행은 model/size/task/seed/eval_T 조합이다. 수렴 목표를 달성하지 못한 run도 누락하지 않고 그 사실과 마지막/best validation 성능을 남긴다.

## 14. OOM·수렴 정체 대응과 변경 관리

개인 연구 기록으로 남기며 별도의 담당자 보고나 기한은 두지 않는다.

- OOM: microbatch를 낮추고 accumulation을 늘려 effective batch를 유지한다.
- 평가 OOM: 두 모델의 측정 batch를 동일하게 낮춘다.
- 여전히 불가능하면 hardware/precision 조건을 재설정하고 새 run으로 기록한다.
- 과제 L,N,M,V를 임의로 줄인 결과는 표준 실험 결과로 사용하지 않는다.
- mixed precision 변경, 학습률 변경, 추가 step은 config가 다른 별도 run으로 관리한다.
- LR/예산 변경 시 두 모델에 같은 비교 조건을 적용하거나 비대칭임을 결과에 명시한다.
- 장시간 수렴 정체 시 최근 train/validation CE, gradient norm, gate 통계, NaN/overflow, sample oracle 결과를 기록한다.
- 기존 checkpoint와 새 구조의 호환성을 추정하지 않는다. 이전 checkpoint는 자동 로드하지 않고 명시적 migration 없이는 오류 처리한다.

## 15. 완료 정의

구현 완료:

1. 새 파일 구조와 독립 모델 계약이 적용되어 있다.
2. 데이터/모델/학습/평가/분석의 필수 검증이 통과한다.
3. 두 모델의 학습·평가 CLI와 GRT 분석 CLI가 동작한다.
4. config, seed, checkpoint, 결과를 재현 가능한 형태로 저장한다.
5. 정답 누출 없이 정확히 지정된 길이·정답 수를 사용한다.

실험 완료:

1. 실행한 Phase와 model/task/size/seed 조합을 명시한다.
2. 기본 길이 수렴 목표 달성 여부와 확장 길이 성능을 보고한다.
3. throughput/memory의 동일 측정 조건을 기록한다.
4. 실패·OOM·운영 변경을 기록한다.
5. 연구 가설과 관측 사실을 구분하여 결과를 정리한다.

실험 수렴 실패는 조사할 연구 결과이며, 모든 확장 길이에서 CE≤0.05를 달성해야만 구현이 올바른 것으로 인정하는 조건은 두지 않는다.
