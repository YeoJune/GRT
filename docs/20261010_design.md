# Remember 공통 실험과 코드 정리 기준

작성일: 2026-10-10. 1단계 코드 검토 후 작성한 기준에 사용자 검토 내용을 반영했다.
2단계 구현은 아래 계약을 따른다. 이전 실행 기준은 `cbc3f36`이며 진행 중인 실험은 해당 checkout에서 마친다.

## 1. 범위

현재 과제는 ARMT 논문의 Associative Retrieval **Remember**다. 저자 RMT baseline과
GRT가 같은 데이터·배치 계약·학습·생성 평가·curriculum을 사용한다. GRT의 router·ALU·register
수식과 초기화는 유지하며 이전 병렬 복원 인터페이스를 Remember 입력으로 교체한다.
GRT 모델 세부 선택과 GPU 수렴은 이후 실험에서 확정한다.

Copy/Reverse/passkey, 구형 RMT 변형·trainer·설정·검사를 운영 코드에서 제거했다.
원본 RMT 파일은 vendor로 이동하고 내용과 hash를 보존했다. 노트북은 템플릿과 최신 실행본
두 개만 남긴다. 임시 문서는 제거하고 나머지 문서·구현 ZIP은 날짜를 붙여 archive에 보존한다.
`runs/`, 제공받은 결과와 checkpoint는 유지한다.

## 2. 원본과 실험 차이

기준 출처는 논문 `2407.04841v2`와
[저자 저장소](https://github.com/RodkinIvan/associative-recurrent-memory-transformer)의
`24cbb9aed62a5748c4045fd928f7f59899f03b24`다.
GPT-NeoX backbone, MemoryCell/RecurrentWrapper, Remember 데이터 함수를 사용한다.
원본의 adapter import만 package-relative로 바꾸고 데이터 함수는 factory로 추출했다.
`src/grt/vendor/armt/SOURCE.json`과 [NOTICE](../third_party/NOTICE.md)에 출처·hash·변경을 기록한다.

당시 생성된 backbone JSON은 공개 checkout에 없으므로 작은 모델의 상세 옵션은 후속 공개
설정 생성기 `5297db7`을 따른다. Appendix E의 4층/D128/약500k 규모와 부합하지만
누락된 JSON의 모든 옵션을 그대로 복원했다고 주장하지 않는다. RMT 파라미터 수는435,456이다.

| 영역 | 현재 처리 |
|---|---|
| 모델·task·내부 loss | 저자 backbone, recurrent memory와 Remember 규약 유지 |
| 학습 | AdamW, value clipping, 단계별 linear scheduler와 best 가중치 전달 유지 |
| 실행 편의 | 단일 CPU/GPU, 재개, TXT, deterministic split, 추가 fixed-length 평가 |
| T4 예산 | batch2048로 명목 샘플 노출 예산을 맞춤; update 수와 scheduler 길이는 원본과 다름 |
| 범위 | 1→2쌍 연결 기능 점검; 논문의200쌍 capacity 실험이나 전체 결과 재현 아님 |

## 3. 데이터와 loss 계약

key/value 길이1의 fact는 `[key, SEP(100), value, EOS(102)]`다.
각 fact를 하나의 세그먼트로 처리하고 마지막 query는 `[query_key, GEN(101), value, EOS]`다.
key/value는0…15, key는 context 내에서 고유하며 value는 중복될 수 있다. query는 저장된
key 중 하나다. padding은 현재 사용하지 않는다.

| 배치 필드 | 의미 |
|---|---|
| `input_ids` | int64 `[B,L]`, teacher-forced answer 포함 |
| `attention_mask` | bool `[B,L]`, 현재 모두true |
| `labels` | raw input IDs; 외부에서 shift하지 않음 |
| `labels_mask` | predictor 위치 mask; 마지막 `value_size+2` 위치true |
| `input_ids_generate` | answer/EOS 없는 fact+query prompt |
| `attention_mask_generate` | 생성 prompt의 bool mask |

원본 loss는 `logits[:,:-1]`, `labels[:,1:]`, `labels_mask[:,:-1]`로 CE를 계산한다.
길이1이면 GEN 위치에서 value, value 위치에서 EOS를 예측하는 두 CE의 평균이다.
context 복원이나 memory 보조 loss는 없다. GRT도 동일한 target·mask·평균을 사용한다.
평가 CE는 teacher forcing이며 exact match는 실제 생성한 value+EOS가 모두 맞는 비율이다.

데이터는 미리 생성한 유한 집합이며 loader는 shuffle하지 않는다. split seed는54/55/56이다.
split 간 같은 연결을 금지하는 별도 holdout 과제는 아니다. 원본 random collator는 effective
batch 전체의 pair 수를 하나 선택하고 뒤쪽 fact를 남긴 뒤 각 예제의 query를 다시 선택한다.
accumulation은 이 collate 이후에 나눈다.

같은 dataset·분포를 두 모델이 공유하지만 전역 Torch RNG를 쓰는 원본 collator 때문에
architecture별 초기화가 다르면 길이·질의의 실제 선택 순서는 다를 수 있다. 이번 정리에서는
baseline의 학습 sequence를 바꾸는 독립 collator RNG를 도입하지 않았다.

## 4. 공통 모델 인터페이스

```python
forward(input_ids, attention_mask, labels=None, labels_mask=None)  # .loss/.logits
generate(input_ids, attention_mask, max_new_tokens, pad_token_id, eos_token_id)
```

두 모델 모두 생성된 토큰 tensor를 반환한다. trainer/evaluator는 모델 이름으로 데이터나
loss를 분기하지 않으며 factory만 모델을 선택한다. RMT는 원본 wrapper를 직접 반환해
`state_dict` prefix를 유지한다. GRT trace는 선택적 `forward_with_trace` capability다.

GRT의 learnable S0, global pooling router, ALU, tied embeddings와 다음 write-back을 유지한다.

`S_next = (1-W) * S + W * candidate`

router는 현재 토큰을 학습 가능한 query로 attention pooling하고 이전 register에 attention하여
read/write sigmoid gate를 만든다. ALU는 토큰과 register를 연결한 Pre-LN 양방향 Transformer다.
기본 conditional read=false, write dropout=0, write bias=-2다. register normalization,
추가 forget gate, memory detach, 별도 readout head는 넣지 않는다.

Remember 연결은 다음과 같다.

1. 완성된 fact마다 기존 router·ALU를 적용하고 write-back을 한 번 수행한다.
2. 마지막 query는 `[query_key, GEN]` prefix만 넣어 value를 예측한다.
3. `[query_key, GEN, teacher_forced_value]`에서 EOS를 예측한다.
4. 두 prefix는 같은 fact memory를 사용한다. query candidate는 다음 prefix의 memory로 쓰지 않는다.
5. 생성 때는 teacher-forced value 대신 실제 예측을 붙인다. loss gradient는 fact write-back까지 전달한다.

따라서 global pooling·양방향 ALU를 유지하면서 미래 정답 누출을 차단한다. RTLA는 실제
fact update만 기록하며 query 재계산을 recurrent update로 세지 않는다.
현재 생성은 미완성 마지막 세그먼트에서 시작하고 그 세그먼트의 답을 생성하는 계약이다.
긴 연속 생성·padding을 추가하려면 데이터와 모델 경계를 함께 확장한다.
GRT의 모델 설정은 보존했으므로 파라미터 수가 RMT와 같지는 않다.

## 5. 교체 경계

`DatasetAdapter`는 task 검증, stage 적용, split 생성, collator, 생성 옵션과 정답 추출을 맡는다.
현재 adapter는 `remember` 하나다. 신규 adapter는 `register_adapter` 또는 `data.name: module:object`로
연결하고 task 고유 옵션은 `data.options`에 둔다. collator는 위 공통 배치를 반환한다.
새 과제 때문에 trainer/evaluator에 token ID나 target 위치 분기를 추가하지 않는다.
현재 stage 설정은 pairs/key 기반이며 다른 curriculum은 adapter/config 경계에서 명시적으로 확장한다.

모델 교체는 factory, 인터페이스 변경은 이 배치·forward/generate 경계에서 처리한다.
새 데이터셋을 미리 구현하거나 범용 framework를 추가하지 않는다.

|---|---|
| 기본 모델 규모 | V128 / D128 / 4층 / 4 heads / FF128 / memory32 |
| 데이터 | train1,000,000 / validation1,000 / test10,000 |
| key/value 길이 | 각각1 |
| curriculum | 1쌍 최대500 → 2쌍 최대2,500 update |
| microbatch / accumulation / effective batch | 2,048 / 1 / 2,048 |
| precision | FP32 |
| optimizer | AdamW, lr3e-4, betas(.9,.999), eps1e-8, weight decay.001 |
| clipping | gradient value1.0 |
| scheduler | warmup=단계 예산10%, horizon=단계 예산2배, linear |
| 평가 | batch512, 100 update마다 random/fixed 길이 평가 |
| best / 단계 전환 | fixed 길이 생성 EM 최대 가중치 / EM≥99% |

명목 샘플 예산은 원본 B512의2,000/10,000 update와 같다. 유한 데이터의 작은 마지막 배치와
조기 종료 때문에 실제 노출량은 다를 수 있으며 `train_samples_seen`에 기록한다.
현재 RMT 측정 peak에서 B2048을 추정했으며 GRT에 같은 VRAM 사용을 보장하지 않는다.
GRT 실험 시 실제 peak/시간을 보고 microbatch·accumulation을 조절한다.

Kaggle T4×2의1→40쌍 목표·분산 실행·15시간 예산은 [별도 실험 기록](20261010_kaggle.md)에 있다.

## 7. 기록과 W&B

로컬 JSON/JSONL/TXT 기록은 항상 남긴다. `wandb.enabled=false`가 기본이며 비활성 상태에서
import·로그인·연결하지 않는다. enabled일 때 optional dependency와 사용자 로그인 환경을 쓴다.
키를 config/checkpoint에 저장하지 않는다.

한 curriculum은 W&B run 하나다. 실제 완료 update를 합친 `global_step`과 stage step·pairs·key를
기록하고 로컬 run ID로 재개한다. train loss/LR/samples/time/peak, random/fixed validation,
최종 test와 단계 종료 결과·실행 metadata를 기록한다. train loss는 해당 update의 배치 값이다.
연결 실패는 `warnings.txt`에 남기며 로컬 학습 결과를 보존한다. 모니터링 전후 RNG를 보존한다.
GRT의 `rtla.enabled=true`에서는 gate·register norm·update 거리와 NPZ/PNG도 남긴다.
read=false인 head를 학습된 읽기 전략으로 해석하지 않는다.


기존 문서의 본문·ZIP을 날짜별 archive로 옮겼다. [목록](README.md)으로 당시 기록을 찾는다.
vendor의 파일명은 원본 대조를 위해 유지한다. 중복 runner/curriculum/구형 interface는 제거했다.

새 checkpoint는 `memory_experiment/2`이며 모델·optimizer·scheduler·RNG·loader 위치를 저장한다.
같은 설정/경로로만 재개한다. 이전 native `author_rmt/1`은 strict-load와 읽기·평가를 지원하며
새 실행으로 자동 migration하지 않는다. 구형 병렬 복원 GRT checkpoint는 호환 대상이 아니다.

## 9. CPU 검증 범위

- 원본 파일 hash, fixture logits/loss/memory/gradient/생성 대조.
- query/target/predictor mask, 데이터 재생성, collate 후 accumulation.
- GRT 미래 정답 차단, fact→query gradient, W=0/1 write-back, conditional read.
- 공통 학습 prefix와 생성의 다음 토큰 일치, stage 전달, 미수렴 정지, 재개 동일성.
- TXT/JSON 대응, W&B 비활성·ID 재사용·단계 step·실패 기록, 모니터링 RNG 보존.
- CLI/노트북 실행 검사, GRT trace 출력, 이전 checkpoint 평가.

정리 전 `cbc3f36`과 정리 후의 작은 RMT를 두 stage 총8update 비교하여 loss·validation,
model/optimizer/scheduler tensor와 Torch RNG의 정확한 일치를 확인했다.
제공된 이전 native checkpoint의512개 fixed validation은 CE≈.3414595, EM=.544921875로 재현했다.
이 결과는 경로 보존 증거이며 GPU 수렴이나 전체 capacity 재현 증거가 아니다.
작은 CPU 검사와 사용자 Colab 실험을 구분하고 후속 GRT 실험에서 세부 조건을 확정한다.
